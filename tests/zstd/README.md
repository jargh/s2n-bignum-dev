# Tests of the specification of zstd's Huffman-coded literals

These files test `common/rfc8878.ml`, the HOL Light specification of the
decoding of Huffman-coded literals in the Zstandard format (RFC 8878,
sections 4.1, 4.2 and 3.1.1.3.1, in one stream or four), against zstd 1.5.7
and against the RFC itself. The specification has a flag `zstd` that
selects the RFC's reading (false) or zstd's (true), which differ only on
some inputs that the RFC rejects and zstd accepts, and on literals in four
streams of fewer than 6 bytes, which zstd rejects (see the head of
`common/rfc8878.ml`). For four streams, zstd's reading is that of zstd
without its fast decoding (the flag `HUF_flags_disableFast`): the fast
decoding, which zstd uses by default, does not check that the streams are
consumed exactly, and accepts many malformed inputs.

* `rfc8878_ref.py` is a Python mirror of the specification. Each of its
  functions follows one of the definitions or inductive relations of the HOL
  file, rather than aiming for speed.
* `zhuf_run.c` is a test program that runs zstd's decoding functions on the
  inputs given to it, and zstd's encoding functions to make test inputs.
  `../../arm/zstd/build_zstd.sh` builds it for AArch64, linked with the
  library whose code is verified (`zhuf_run`), and linked with the same
  object files of the decoding instead (`zhuf_run_direct`), which is needed
  for four streams, which the library has no entry point for; it can also be
  built natively with zstd's sources, for example as

      gcc -O2 -DZSTD_DISABLE_ASM -I$Z -I$Z/common -o zhuf_run zhuf_run.c \
        $Z/common/{entropy_common,fse_decompress,error_private}.c \
        $Z/decompress/huf_decompress.c \
        $Z/compress/{huf_compress,fse_compress,hist}.c

  where `$Z` is the `lib` directory of zstd (`-DZSTD_DISABLE_ASM` is for
  x86-64, where zstd otherwise uses some assembly code).
* `difftest.py ZHUF_RUN SEED N` compares zstd, through `zhuf_run`, with the
  mirror, on Huffman-coded literals from zstd's encoder, on mutations of
  them, on raw and FSE-compressed tree descriptions with random and crafted
  weights and normalized counts, on prefix codes up to 12 bits long, on FSE
  table descriptions alone and on random bytes. It checks acceptance and the
  output of `HUF_decompress1X1_DCtx_wksp`, `HUF_readStats` and
  `FSE_readNCount`: zstd must agree exactly with zstd's reading in the
  mirror, and the RFC's reading must agree with zstd except where it
  rejects the input for a reason in the list `allowed` there. With
  `zhuf_run_direct`, it also checks literals in four streams, from zstd's
  encoder and crafted, and malformed variants of them, decoded by
  `HUF_readDTableX1_wksp` and `HUF_decompress4X_usingDTable`: without the
  fast decoding, zstd must agree exactly with zstd's reading, and with it
  zstd must give the same output wherever the mirror accepts the input (it
  counts the malformed inputs that the fast decoding accepts). It reports
  which features of the format were reached.
* `appendix_a.py RFC8878_TXT` checks the mirror's FSE decoding tables for
  the predefined distributions against the tables of Appendix A of the RFC.
* `rfc8878_checks.ml` makes the same check of the HOL definitions, and
  should end with `appendix_a_ok = true` (it takes a few minutes).
* `rfc8878_eval.ml` defines `HUF_DECOMPRESS1X1_RULE zstd bs n`, which
  proves `huf_decompress1x1 zstd l out` for a concrete input `l` and the `n`
  bytes `out` it decodes to, by following the relations of the
  specification step by step. `hol_tests.ml`, generated by
  `make_hol_tests.py`, uses it on small inputs of every kind and checks the
  output against zstd's, in both readings where the RFC accepts the input,
  and `HUF_DECOMPRESS4X1_RULE` likewise on small literals in four streams.

The tests also found two errors in the RFC's examples: the stream of the
example of section 4.2.2 decodes to 0154, not 0145, since its Table 26
swaps the codes of the symbols 4 and 5 (erratum 8195), and each table of
Appendix A has its first row twice (erratum 6441). With four streams, the
fast decoding of zstd 1.5.7 accepts, for example, a stream with a byte
more at its start than its codes use, or one byte less, or with a last
byte of 0, or the sizes of two streams swapped in the jump table, which
the RFC says make the decoding faulty (section 4.2.2); without the fast
decoding, zstd rejects them.

From the repository root, run for example

    python3 -I -B tests/zstd/difftest.py <build>/zhuf_run_direct 1 300
    python3 -I -B tests/zstd/appendix_a.py rfc8878.txt

and in HOL Light, `loadt "tests/zstd/hol_tests.ml";;`, which should end
with `hol_tests_ok = true` and `hol_tests4_ok = true` (it takes about a
quarter of an hour).
